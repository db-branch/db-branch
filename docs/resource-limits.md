# リソースの上限

1 つのブランチやアップロードがノード全体を巻き込まないための上限。すべて Settings（`core`）で変える。

| 設定 | 既定 | 働き |
|---|---|---|
| `branch.refquota_gb` | `0`（無制限） | 新しく作るブランチのデータセットに ZFS `refquota` を設定する。超えたブランチだけが書き込みエラーになる。チェックポイントの復元で作り直したデータも同じ上限になる（ZFS が拒否した場合、復元は止めずにログだけ残す）。既存のブランチには遡って付かない |
| `branch.max_per_user` | `0`（なし） | 所有者ごとの最大ブランチ数。超える作成は `429 quota_exceeded`。所有者のないブランチ（ログインなしの作成など）には効かない。`failed` のブランチも数える |
| `branch.max_ttl` | なし | TTL の上限。TTL なしで作ったブランチにはこの値が付く。これを超える作成・延長は `400 invalid_request` |
| `base.refresh_max_gb` | `0` | 定期 refresh のソースダンプの上限。超えたらダンプを止めて消す |

## プールの空き容量

設定なしで常に効く。ZFS プールの空きが **1GiB または 10% の大きいほう** を下回ると、新しくデータを増やす操作（ブランチ作成、ベース作成・ロード、チェックポイント保存、refresh）を `507 no_space` で拒否する。プールの容量を読めないときも拒否する。

## メモリ

- 一時停止（`paused`）のブランチはノードのメモリ予算に数えない。
- 再開（resume）は、ノードのメモリ予算に空きがなければ `503 no_capacity` で拒否し、ブランチは一時停止のまま残る。他のブランチを一時停止または削除してから再開する。
- 単一ノードでも、ホストのメモリ（と ZFS ARC の上限）から予算を計算する。

## アップロードと refresh のダンプ

- 並行するアップロードは、受け付け済みの容量を互いに差し引いて空きを判断する（同時に送ると空きを超える、ということがない）。
- refresh の作業ディレクトリに残った本番ダンプ（未マスク）は、エージェントの起動時に削除する（refresh が実行中なら触らない）。ダンプ中はサイズとディスクの空き（1GiB 未満で停止）を監視する。
