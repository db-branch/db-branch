# ライセンスの月額・年額と自動更新

有償モジュールのライセンスは、一括払いのキーのほかに、月額・年額のサブスクリプションでも買える。サブスクリプションのキーは短い期間（月額なら 1 か月）で期限が来るので、クラスタが新しいキーを自分で取りに行く。キーの形式と署名は [modules.md](modules.md) のとおりで、このページは更新の仕組みだけを書く。

## キーに加わった項目

`pkg/ext/license.License` に次の項目が加わった（どれも省略できる。古いキーとモジュールには影響しない）。

| 項目 | 内容 |
|---|---|
| `billing` | `monthly` / `yearly`。空は一括払いで、手で貼り替える従来のキー |
| `subscription` | サブスクリプションの ID（意味のない文字列）。空でなければ、このキーはオンラインで更新できる |
| `renew_url` | 更新を受け付ける https の URL |

## 更新の流れ

1. 更新するのは**リーダーのノードだけ**。ほかのノードはネットワークに出ない。リーダーになって約 1 分後に最初の確認をし、その後は 12 時間ごと（±1 時間のばらつき）に確認する。リーダーが替わったときの一瞬を除いて、クラスタ全体で同時に出る要求は 1 つ
2. 保存されているキーに `subscription` と `renew_url` があり、期限までが月額なら 7 日未満、年額なら 30 日未満（`billing` が空なら 30 日）になったとき、または期限を過ぎて猶予期間にいるときに、要求を出す
3. `POST <renew_url>`、本文は `{"key":"<いまのキー全体>","cluster":"<クラスタ ID>"}`、`cluster` は、クラスタ ID がまだ作られていないときだけ省く。ヘッダーは `User-Agent: db-branch/<版>` と JSON の `Content-Type` / `Accept` だけ。タイムアウトは 15 秒、リダイレクトは辿らない
4. 応答

   | 応答 | 意味 | クラスタの動き |
   |---|---|---|
   | 200 `{"key":"…"}` | 新しいキー | 下の検査に通れば保存する（`renewed`） |
   | 204 | まだ新しいキーがない | 次の確認を待つ（`not_yet`） |
   | 402 `{"error":{"code":"subscription_inactive",…}}` | 解約または未払い | 通知する（`inactive`）。いまのキーは期限まで使える |
   | 400 / 401 | キーを知らない | `error` として記録する |
   | 429（`Retry-After` 秒つき） | 同じライセンスの更新が多すぎる | 失敗に数えず通知もしない。次の確認は `Retry-After` 秒後（最短 1 分、最長 7 日。値がなければ 1 時間）。結果は `not_yet` |
   | そのほか・通信失敗 | | `error`。1 回目は 1 時間後、続けて失敗したら 6 時間後に再試行する |

5. 受け入れる条件。どれか 1 つでも満たさなければ、今のキーを残して `error` と理由を記録する
   - 組み込みのルート鍵で検証できる
   - `ID` と顧客（`Customer`）がいまのキーと同じ
   - 期限（`Expires`）がいまのキーより後。ただし期間の途中でプラン・請求・ノード上限が変わったキーは期限が延びなくてもよく、そのときは発行日時（`IssuedAt`）がいまのキーより後であること
   - いま有効なモジュールのうち、いまのキーが挙げているものを、新しいキーも含む（いまのキーが全モジュール `*` なら、新しいキーも `*`）
   - 期限内か猶予期間内であること。新しいキーのノード上限がクラスタのノード数を下回っても保存する（`over_nodes` の通常の警告が働く）。その場合は更新の `message` に「新しいキーは N ノードまで、クラスタは M ノード」と出す
6. 保存は、管理者がキーを貼り付けたときと同じ設定 `license.key`（Raft で全ノードに複製）。モジュールは次の設定の適用で新しいキーを受け取る。**モジュールの有効・無効は変えない**（貼り付けと違い、新しいキーが含むモジュールを自動では有効にしない。管理者が止めたモジュールを更新で勝手に戻さないため）。更新そのものは Raft のコマンドを増やさない（クラスタ ID の記録だけは増える。下の「送る情報」を参照）

## 送る情報

更新の要求に含まれるのは、次の 2 つだけ。

- 現在のライセンスキー
- クラスタ ID（匿名）

ホスト名・IP アドレス・ノード名・使用量・データベースやブランチの中身は送らない。通信先は、キーに入っている `renew_url` だけ。

### クラスタ ID

- 32 桁の小文字 16 進（例: `0123456789abcdef0123456789abcdef`）。乱数だけで作る。ホスト名・IP アドレス・パスワード・トークン・キーなど、既存の値から計算したものではない
- 目的: ライセンスキーは 1 つのクラスタ用。ライセンスサービスは、同じキーが複数のクラスタから使われているときに気づき、キーの持ち主に知らせるためだけにこの ID を使う。使えなくしたり、更新を止めたりはしない。ID を理解しないサービスでも、更新は今までどおり動く
- クラスタごとに 1 つ。全ノードで同じ値で、再起動・リーダーの交代・ノードの追加・版の更新をしても変わらない。別々に作った 2 つのクラスタでは違う値になる
- 作る時期: 最初の更新の要求を出すとき、リーダーが乱数で作って Raft の状態（単一ノードなら `state.json`）に保存する。2 つのノードが同時に作ろうとしても、先に保存された 1 つだけが残る（コマンド `init_cluster_id`、**プロトコル 17**。一部のノードが古い版のあいだは書かれず、その間の要求は ID なしで出る。全ノードが新しい版になれば、次の要求で作られる）
- 古い版のノードは、状態に増えた `cluster_id` を読み飛ばすだけで、壊れない
- 単一ノードがクラスタになるときは、`state.json` の ID を引き継ぐ
- 画面と API には出さない。設定で切るものでもない。ライセンスサービスに一切接続したくないときは、`license.auto_renew` をオフにする（ID も送られない）
## 設定

| 設定 | 既定 | 内容 |
|---|---|---|
| `license.auto_renew`（core） | `true` | 「Renew the licence automatically」。オフにすると、このクラスタはライセンスサービスに**一切接続しない**。画面の「Check now」も使えない |

## エアギャップのクラスタ

外部に出られないクラスタは `license.auto_renew` を `false` にして、新しいキーを手で貼り付ける（Modules → License）。サブスクリプションのキーでも貼り付けは使え、貼り付けたキーは自動更新のキーと同じ扱いになる。月額だと毎月の作業になるので、エアギャップのクラスタには年額か一括払いのキーを勧める。新しいキーの渡し方（メールなど）は販売側で決める。

## 状態と画面

- `GET /v1/license` の `renewal`: `enabled`、`last_attempt`、`last_result`（`renewed` / `not_yet` / `inactive` / `error` / `unknown`）、`message`、`next_attempt`。状態はリーダーのメモリにあり（再起動で消える）、リーダーでないノードは、リーダーに聞いて答える。聞けなければ `unknown`
- `POST /v1/license/renew`（管理者）: 期限に関係なく、いま問い合わせる。30 秒に 1 回まで。自動更新がオフ、またはキーにサブスクリプションがないときは `409`
- コンソールの Modules → License に、プラン・請求（Monthly / Yearly）・「Renews automatically」・次の確認と前回の結果・「Check now」・設定へのリンクを出す

## 通知

[notifications.md](notifications.md) の `license.renewal_inactive`（解約・未払いで更新できない）と `license.grace`（猶予期間に入ったのに更新が失敗している）。どれも、同じ期限につき 1 回。

## 開発用

開発ビルド（`-tags dev`）は `internal/app/license_root_dev.go` のルート鍵を使う。テストはローカルの署名鍵でキーを作る。本番の鍵はリポジトリに置かない。

## Web サイト（FAQ・料金ページ）に書くこと

サイトはこのリポジトリにない。次を載せる。

- 月額と年額がある。年額の価格（月額の何か月分か）と、どちらもいつでも解約できること。解約後も、すでに払った期間の終わりまでは使える。そのあと猶予日数ぶん動き続けて止まる。止まるのは有償機能だけで、ブランチやデータベースは止まらない
- 自動更新: 期限の近づいたキーを、クラスタのリーダーが HTTPS でライセンスサービスから取得して保存する。キーを手で貼り替える作業はいらない
- 送る情報: 現在のライセンスキーと、匿名のクラスタ ID（乱数で作った 32 桁。`User-Agent` に db-branch の版）。ノード名・ホスト名・IP アドレス・使用量・データベースの中身は送らない。キーにはサブスクリプションの ID が入っている。クラスタ ID は、1 つのキーが複数のクラスタで使われていないかを、サービスが気づいて持ち主に知らせるためのもの。使えなくしたり、更新を止めたりはしない
- 外に出られない環境: 設定 `license.auto_renew` をオフにすればライセンスサービスへ一切接続しない。そのときは新しいキーを貼り付ける。エアギャップには年額か一括払いを勧める
- 支払いが止まったとき: 管理画面と Slack・Webhook の通知で知らせる。キーは期限まで使え、猶予日数のあいだも動く
- ノード数の上限、Team / Business の違いは従来どおり
