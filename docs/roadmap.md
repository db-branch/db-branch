# db-branch ロードマップ

現在地: **1.0 (GA) 準備完了（`main`）**（`v0.3.1` 以降に 1.0 向けの契約固定・品質強化・形式検証を反映）

本ドキュメントは、`db-branch` の **1.0 (GA)** スコープと GA 後の展開をまとめた公開ロードマップです。日付の約束は行わず、**直近の完了実績** とフェーズ（**Now / Next / Later**）およびステータス（**完了 / 検討中**）で示します。仕様の確定状況やフィードバックにより順序・内容は変更されることがあります。

## 直近の完了実績（`v0.2.7` 以降・`main` マージ済み）

`v0.2.7` で実施した実行権限分離・DB ログイン非スーパーユーザー化・ソケット保護に続き、以下の機能が `main` ブランチへマージされています。

- **ランタイムモジュール標準化（コア基盤）**: コアの DB エンジン契約（`RuntimeRegistry` / `RuntimeProvider` / `RuntimeCaps`）の抽象化、外部ランタイム向け gRPC 契約（`pkg/ext/proto/runtime/v1`）、署名検証・エンジン別非特権 OS ユーザー分離、適合検査ツール（`db-branch-conformance`）、GitHub Releases からの導入・管理 CLI（`module install` / `remove` / `list` / `trust`）、外部エンジンでの `branch upgrade`・ダンプ入出力対応を完了しました。
- **モジュール運用・エコシステム整備**: 削除済みモジュール記録をクラスタから消去する `module forget` を追加し、データマスキング用モジュール（`anon` / `greenmask` / `greenmask-mysql`）を本体リポジトリから別リポジトリへ分離しました。あわせて Web コンソールの無償モジュール表示修正や GitHub Sponsors 導線を追加しました。
- **Branch Fork・Branch Line Merge・1.0 契約固定・形式検証**: `branch fork`、`branch merge`（テーブル単位のダイジェスト最適化含む）、セキュリティ・リソース保護・Debian パッケージング・API / CLI / OpenAPI (`1.0.0`) / MCP / Web コンソール修正、さらに Lean 4 認可モデル検証を `main` に統合しました（詳細は [CHANGELOG.md](../CHANGELOG.md) を参照）。
- **ClickHouse ランタイムモジュール（別リポジトリ・Beta）**: 外部ランタイムモジュール契約上で動作する ClickHouse 対応を別リポジトリ [db-branch-rt-clickhouse](https://github.com/db-branch/db-branch-rt-clickhouse) として公開し、Beta 版（`v0.2.0`）をリリースしました。

## 1.0 (GA) のスコープと位置づけ

1.0 リリースに向けて、以下のスコープと制約方針を確定しています。

- **コア組み込みエンジン**: **MySQL / PostgreSQL** を引き続きコアに同梱（built-in）し、単一ノードおよび Raft クラスタ双方で 1.0 GA 対象とします。
- **外部ランタイムモジュール**: 1.0 では **Experimental（実験的機能）・単一ノード限定** として提供します（クラスタ構成では制限・警告を表示します）。クラスタ公式対応および Web コンソールでの全面対応は GA 後とします。
- **ClickHouse 対応**: 1.0 本体のスコープには含めず、別リポジトリ [db-branch-rt-clickhouse](https://github.com/db-branch/db-branch-rt-clickhouse) で外部ランタイムモジュール（現在 Beta）として独立して開発・提供します。
- **`base mask` の扱い**: マスカー本体を別リポジトリへ分離したことに伴い、**1.0 では API / CLI / Web コンソール / MCP から一時的に非公開（非露出）** とします（コア内部の拡張ポイント基盤は維持します）。機密データを含む環境では、引き続きベース作成前にマスク済みダンプを用意する運用を推奨します。
- **拡張ポイントの 1.0 互換契約**: 1.0 で後方互換性を保証する公開契約は **`pkg/ext`（インターフェース型）** と **`pkg/ext/proto/runtime/v1`** です。従来の `pkg/ext/plugin`（`net/rpc`）は **内部向け・非推奨（deprecated）** 扱いとし、1.0 公開契約の対象外とします。
- **サポート対象 OS**: 公式サポート対象は **Ubuntu 24.04 LTS / 26.04 LTS**（amd64 / arm64）です（Debian 12 等は対象外とします）。
- **GA 後（1.1 以降）に送る項目（1.0 の制約として文書に明記）**:
  - **ブランチ DB サーバー通信の TLS 対応**: 1.0 ではプライベートネットワークまたはプロキシ経由での利用を前提とします。
  - **バックアップファイルの保存時暗号化**: 1.0 ではファイルシステム権限および保管先ストレージ側での暗号化を前提とします。
  - **PostgreSQL メジャーバージョンアップグレード（`pg_upgrade`）**: 1.0 の `branch upgrade` は MySQL のメジャー／シリーズ移行と PostgreSQL の同一メジャー内マイナー更新までを対象とします。

## フェーズ別詳細

### Now: 1.0 (GA) に向けた品質・セキュリティ・契約固定（進行中）

既存機能を 1.0 として安心して本番評価・長期運用できる品質へ引き上げ、1.0 以降の破壊的変更を避けるための契約固定を進めます。

- **セキュリティと権限境界の強化**:
  - 認証・認可・入力検証・プロセス隔離など、多層防御を全体にわたって強化します。
  - コンソール HTTPS について、`config.toml` からの証明書パス指定（再起動なしの更新反映を含む）、TLS 1.3 必須化、自己署名証明書の有効期間短縮（825 日以下、825 日超の既存証明書は再生成）を行います。
- **クラスタ・障害回復・ルーティングの堅牢化**:
  - 故障・退役ノードを取り除く `cluster remove` / `cluster leave` を実装し、ローリングアップデートの検証と、障害後の状態復旧を強化します。
  - ProxySQL ルーティングの堅牢化とあわせて、ProxySQL 3 におけるセッション・prepared statement・一時テーブルの互換性検証と推奨設定の文書化を進めます。
- **リソース保護**:
  - ブランチ作成時の ZFS `refquota` 上限、プール最小空き容量ガード、ユーザー別の最大ブランチ数・最大 TTL を、設定で強制できるようにします（既定は従来どおり無制限）。
  - 一時停止中（`paused`）ブランチのメモリ配置計算を適正化し、単一ノード環境での監視メトリクス・通知・メモリ上限制御を整備します。
- **API・CLI・MCP・Web コンソールの 1.0 契約固定**:
  - REST API のアクション名整理、一覧 API の `next_cursor` 統一、MCP 引数名の統一（移行期間中は旧名も受理）、OpenAPI `1.0.0` の完全同期を行います。
  - SQL 実行や Web コンソールの不具合修正、日本語 UI の文言統一（ナビゲーション・専門用語は英語を維持し、説明文・確認ダイアログ・エラーを日本語化）を完了します。
- **パッケージング・ドキュメント総点検**:
  - Ubuntu 24.04 / 26.04 LTS での `.deb` 新規導入・アップグレード・削除／完全削除（`apt remove` 時はデータ保護のため稼働中 DB を残す現仕様や、PostgreSQL `full_page_writes = on` 維持方針を含む）を検証し、公開ドキュメントを実装と一致させます。

### Next (1.0 対象): Branch Fork — 既存ブランチからの分岐（計画中）

ベーススナップショットだけでなく、既存の稼働中（`ready`）または一時停止中（`paused`）ブランチの現在状態や過去のチェックポイントから、独立した子ブランチを数秒で切り出せるようにします。

- **主な機能**:
  - 親ブランチに影響を与えない独立したデータセット・ポート・DSN を持つ子ブランチの即時作成
  - 親ブランチの一時停止なしでのフォーク、および整合性を重視する `--clean` オプション
  - CLI (`db-branch branch fork`)、REST API (`POST /v1/branches/{name}/fork`)、MCP (`fork_branch`)、Web コンソールからの操作
  - 所有権・可視性・容量ガードなど 1.0 のセキュリティおよびリソース保護ポリシーを子ブランチにも一貫適用
- **v1 スコープ外**: クラスタ内の別ノードをまたぐクロスノードフォーク、共有ストレージ環境でのフォーク、匿名ユーザーによるフォーク。
- **統合について**: 子ブランチを親や他のブランチへ統合する機能はありません（統合は次項の同一ブランチ内の履歴ラインに限ります）。

### Next (1.0 対象): 同一ブランチ内の履歴ラインマージ — Branch Line Merge（計画中）

`branch restore` によって **1 つのブランチ内** で分岐・退避された過去の履歴ラインの変更を、現在稼働中のライブラインへ安全に統合できるようにします。

- **主な機能**:
  - 共通祖先を起点とした 3-way 論理比較（行単位の挿入・更新・削除とスキーマ整合性の検査）
  - 実行前に影響を確認できる Dry-run プレビュー（CLI / API / MCP / Web コンソール）
  - 適用前の自動チェックポイント取得と、失敗時の自動ロールバックによる安全性確保
  - コンフリクト検出時はライブラインを一切変更せずに競合箇所を報告
- **対象外**: 異なるブランチ間のマージ（方針として提供しません。下記参照）、対話的なコンフリクト解決 UI、共有ストレージ環境。
- **「ブランチ同士はマージ・リベースしない」方針との関係**: db-branch は使い捨て（disposable）のサンドボックスを前提としており、**別々のブランチ間で並行して行われた書き込みを Git のようにマージ／リベースする機能は提供しません**（[README の Design notes](../README.md#design-notes-and-trade-offs) 参照）。本機能はそれとは別物であり、**同じ 1 つのブランチの内部**で `branch restore` によって退避された履歴ライン（line）を、共通祖先との 3-way 比較で同じブランチの現在状態へ取り込む操作に限られます。

### Later (GA 後): 1.1 以降の機能拡張・エコシステム発展（検討中）

1.0 リリース後、後方互換性を保ちながら以下の拡張を段階的に進めます。

- **セキュリティ・運用の強化**:
  - ブランチ DB サーバー通信の TLS 対応
  - バックアップファイルの保存時暗号化・認証
  - クラスタ PKI の運用機能の拡充、拡張／ランタイムモジュール子プロセスの自動再起動、単一ノード環境でのバックアップ対応
- **データベースエンジン・バージョン対応の拡充**:
  - PostgreSQL メジャーバージョンアップグレード（`pg_upgrade`・拡張互換性チェック・ロールバック）の設計と対応
  - MySQL / PostgreSQL の任意バージョン指定ダウンロードおよび glibc・共有ライブラリ差異の事前検証（[#23](https://github.com/db-branch/db-branch/issues/23)）
  - 外部ランタイムモジュールのクラスタ公式対応・Web コンソール完全統合、および [db-branch-rt-clickhouse](https://github.com/db-branch/db-branch-rt-clickhouse) の正式版化
  - マスカーエコシステムの整備にあわせた `base mask` 導線の再公開
- **ブランチ運用・ワークフローの拡充**:
  - 一定時間アイドル状態が続いたブランチの自動破棄またはクリーン状態への自動リセット（GC）
  - クロスノードでの Branch Fork

## 1.0 (GA) の定義

`v1.0.0` のリリースにあたり、以下の条件を満たすことを目標としています。

1. **API・CLI・MCP の安定化**:
   - REST API (`/v1/...`) および OpenAPI `1.0.0` 仕様の破壊的変更を行わない契約の確立（Semantic Versioning の厳格適用）。
   - CLI サブコマンド体系・JSON 出力・MCP ツール引数名の整理と固定。
2. **互換性保証**:
   - クラスタのローリングアップグレードにおける Raft プロトコルおよび状態データの後方互換性保証。
   - 公開拡張契約 **`pkg/ext`**（インターフェース型）および **`pkg/ext/proto/runtime/v1`** の安定化（`pkg/ext/plugin` は内部・非推奨扱い）。
3. **セキュリティとリソース保護**:
   - 認証・認可・監査ログ・通知・プロセス隔離などの多層防御、および ZFS `refquota`・空き容量ガード・ユーザー別上限の整備。
   - GA 後に送る項目（DB サーバー TLS、バックアップ暗号化、PostgreSQL メジャーアップグレード）および実験的機能（外部ランタイムの単一ノード限定）の境界を文書に明記。
4. **パッケージングと運用性**:
   - 公式サポート対象 OS（Ubuntu 24.04 LTS / 26.04 LTS、amd64 / arm64）での `apt install db-branch` による新規導入・`0.2.x → 1.0.0` アップグレード・削除検証。
   - 監視メトリクス、通知、故障ノード削除を含む障害復旧手順の整備。
5. **ドキュメントの網羅**:
   - 公開ドキュメント（英語・日本語）と OpenAPI リファレンスが 1.0 の全機能・設定・制約・運用手順と一致していること。
